## 现象

执行官方安装脚本时，进度停在 `0.0%`，或干脆超时退出：

```bash
curl https://get.acme.sh | sh
```

重试多次结果一致，脚本无有效报错。

## 根因

安装脚本自身要从境外源拉取主程序与依赖。网络受限时，连接能建立但**数据不流动**，表现为下载 0 字节、长时间挂起，而不是明确的 404 或连接拒绝。

因此「重试」不会改变结果：不是瞬时抖动，而是稳定被阻断。

## 处置

按优先级：

1. **使用镜像源**：换成境内镜像的安装地址（或 `--repo` 指定镜像仓库）。
2. **走 HTTPS 端口替代**：镜像不可用时，用 SSH over 443 一类替代通道拉取。
3. **包管理器分发**：发行版仓库里若有对应包，直接安装，避开脚本拉取。

已签发的证书不受影响——重新安装客户端不影响证书文件本身。

## 证据

- 修复前：官方源下载长时间停在 `0.0%`，多次重试无变化。
- 换镜像后安装完成，耗时数秒；`acme.sh --version` 正常输出。
- 原有证书目录未变更，Nginx 继续使用原证书正常提供 HTTPS。

## 教训

- 「下载 0 字节」与「连接失败」是不同故障：前者说明被限速/阻断，重试无效。
- 安装客户端与续签证书是两件事，客户端重装不需要重新签发。
- 受阻断的资源应固定用镜像，写进部署文档，避免每次都重新试错。

## 适用边界

- 适用：受限网络中安装境外分发的 CLI 工具（acme.sh、nvm、各类 install.sh）。
- 不适用：网络正常环境（直接用官方源更可靠）；镜像长期不同步的场景需回退官方源并做版本校验。
