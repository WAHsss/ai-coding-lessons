## 现象

站点发布后出现两类问题：

- 访问首页落到目录列表或 403；
- 站点目录里混入源码、`.git`、设计稿、依赖目录等无关文件，体积异常或泄露内部文件。

## 根因

直接从项目根目录打包，把「源目录结构」当成「站点产物」：入口不固定、排除规则缺失。

静态服务只认「根目录 + 入口文件」，源目录里的其他内容对它没有意义。

## 处置

1. **固定入口**：站点根目录必须有 `index.html`，不依赖目录默认行为。
2. **显式排除清单**（示例）：

   ```
   排除：.git/  node_modules/  src/  docs/  *.md  *.map  *.ts
   ```

3. **打包后自检**：列出产物文件清单，确认只含站点资源；再 `curl -I` 首页应返回 `200`。

   ```bash
   curl -sS -o /dev/null -w '%{http_code}\n' https://<domain>/
   ```

## 证据

- 修复前：首页 403、目录可列出无关文件。
- 使用排除清单并固定 `index.html` 后，首页 `200`，产物清单只含 HTML/JS/CSS/图片。
- 站点体积明显下降，未再出现源码文件被公网访问的情况。

## 教训

- 「打包」不等于「压缩目录」：产物清单要显式定义，而不是靠默认行为。
- 入口文件写死，能同时避免 Nginx 目录行为差异。
- 发布后必须核对首页状态码与产物清单，这两项能覆盖大多数静态站点事故。

## 适用边界

- 适用：Nginx / 对象存储托管的纯静态站点。
- 不适用：SSR / 需要服务端路由的应用（入口与产物规则完全不同）。
