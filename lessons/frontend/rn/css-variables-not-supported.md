## 现象

主题色、间距等用 CSS 变量定义：

```scss
:root { --brand: #1677ff; }
.btn { color: var(--brand); }
```

H5 正常，RN 端该属性**完全丢失**：颜色回到默认值，或元素出现无样式状态，且构建不报错。

## 根因

RN 没有 CSS 自定义属性机制。变量在样式编译阶段被 `postcss-css-variables` 处理：

- 变量在当前文件（含其 import 链）**有定义** → 内联为字面量，可正常工作。
- 变量**未定义**（定义在另一个未被该模块引入的文件里）→ `var()` 整段被替换成 `undefined`，属性失效。

关键点是「按文件解析」：变量是否可见取决于该模块的编译上下文，而不是「全局定义了就应该生效」。

## 处置

按成本从低到高：

1. **编译期注入 token 块**：sass 阶段向需要变量的文件注入 `:root { --brand: ... }`，保证每个使用方都能解析到定义；数值仍保持单一来源（只在一处维护）。
2. **直接内联字面量**：由 sass 变量（编译期）替代 CSS 变量，产物中不再出现 `var()`。
3. **平台差异文件**：仅在 RN 使用 `index.rn.scss`，写入具体值。

优先 1：改动集中在一处构建配置，不触碰存量 SCSS。

## 证据

- 修复前：RN 端相关属性丢失，无报错；产物中可见 `undefined` 替换痕迹。
- 注入 token 块后 RN 构建成功，样式与 H5 一致；H5 产物无变化。
- 同类机制在样式子集条目中同源（见 GEN-RN-0006）。

## 教训

- 跨端主题用 CSS 变量时，先确认「每个使用方文件能否解析到定义」，而不是确认「全局有没有定义」。
- 变量失效是静默的：没有报错，只有视觉差异，必须靠真机取帧核对。
- 主题 token 保持单一来源 + 编译期注入，比在每个文件重复写值更可持续。

## 适用边界

- 适用：Taro RN / RN 中复用 Web SCSS 主题变量的场景。
- 不适用：H5 / 小程序（原生支持 CSS 变量）；运行时切换主题且需要动态改色（RN 应改为 JS 侧主题对象 + 重新渲染）。
