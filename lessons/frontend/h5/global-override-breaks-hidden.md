## 现象

组件库的弹层 / 下拉在应当隐藏时**仍然可见**，或出现「点了才显示、关不掉」；删除某段全局 CSS 后恢复正常。

## 根因

组件库用「**隐藏类**」实现显隐，例如：

```css
.hidden { display: none !important; }
```

全局覆写规则若带更高特异性（多层选择器、`!important`、属性选择器），会覆盖隐藏类的 `display`，导致隐藏失效。

关键点：隐藏类本身是**弱选择器**，专门为了让业务样式能覆盖；但全局覆写方向恰好相反——覆盖了本不该覆盖的属性。

## 处置

全局规则**只补页面自身未声明的属性**，不改库控制显隐/定位的属性：

- 允许：颜色、字号、圆角等表现属性。
- 禁止：`display`、`visibility`、`position`、`z-index`。

需要覆盖显隐时，改为在**组件作用域**内写规则（带上业务容器类名），不要用全局选择器。

## 证据

- 修复前：弹层隐藏失效；移除全局覆写后恢复正常。
- 收敛作用域后，隐藏类生效，弹层按预期显示/关闭。
- 同页其他表现属性覆写保持生效，说明问题只在显隐类被击穿。

## 教训

- 「库的显隐失效」先查全局 CSS 是否覆盖了 `display` 一类控制属性。
- 全局覆写要按属性白名单管理，而不是按组件随意加。
- 隐藏类带 `!important` 仍可能被更高特异性规则击败，别把 `!important` 当保险。

## 适用边界

- 适用：H5 项目引入第三方 UI 库并做全局样式定制。
- 不适用：CSS-in-JS 或样式隔离（Shadow DOM）环境；仅用库默认样式的项目。
